# Rakuku 要件定義書

> 英語学習アプリ「Rakuku（ラクク）」の MVP 要件定義書。
> 本書は「誰が読んでも同じ実装に到達できる」ことを目標に、確定事項・前提・未確定事項を明示する。

- **版**: v1.0（MVP）
- **最終更新**: 2026-06-04
- **ステータス**: 確定（全項目決定済み。§11/§12 参照）

## 1. 概要

| 項目 | 内容 |
|---|---|
| アプリ名 | Rakuku（ラクク） |
| ジャンル | 英語学習（出会った英語表現を保存して、AI解説・音声・復習で定着させる） |
| 対象プラットフォーム | iOS / Android（クロスプラットフォーム） |
| 開発フレームワーク | Flutter |
| バックエンド | Supabase |
| 生成AI | Claude（Anthropic） |
| 収益モデル | 無料（MVP）。将来の収益化は別途検討 |
| 主言語 | UI・AI解説ともに日本語 |

### 提供価値（コンセプト）

日常で出会った英語（Webページ・SNS・記事・チャットなど）を**アプリを開かずに最短手数で保存**し、
保存した表現を **Claude が日本語で解説・例文化**、**音声で発音確認**、**復習テストで定着**させる。
「保存のハードルを限りなく下げ、後からまとめて学習・復習する」体験を中心に据える。

## 2. スコープ

### 2.1 MVP に含む

- 共有（Share）経由でのコンテンツ保存（アプリを開かず保存）
- 保存表現に対する Claude による日本語解説・例文生成
- 保存表現の音声生成・再生（発音確認）
- 単語帳（コレクション）管理：一覧・詳細・削除
- 復習機能（2モード）
  - 音声クイズ
  - タイピング想起（日本語の意味を見て英語を入力）
- 認証：Google サインイン ＋ 匿名スタート（後から本登録へ昇格）
- 複数端末間のデータ同期

### 2.2 MVP に含まない（将来検討）

- プッシュ通知 / リマインダー
- SRS（間隔反復スケジューリング）※ §6.5 に簡易版の代替を定義
- フラッシュカード形式の復習
- 穴埋めテスト形式
- 収益化（課金・サブスク・広告）
- ソーシャル機能（共有・フォロー等）
- Web 版

| 用語 | 定義 |
|---|---|

## 5. 機能要件

### 5.1 コンテンツ保存（共有から）

- iOS の共有シート / Android の共有インテントから Rakuku を呼び出し、**アプリ本体を前面に出さずに**テキストを保存できる。
- 受け取る入力：選択テキスト（必須）、可能であれば出典 URL / アプリ名（任意・メタ情報として保持）。
- **MVPの保存対象はテキストのみ**（URL本文取得・画像OCRは将来拡張）。
- 保存時の挙動：
  - オフラインでも保存はローカルに完了する（後で同期）。
  - 保存直後は「未処理（AI解説・音声が未生成）」状態。AI生成は非同期で実施。
- アプリ内からの手動追加（テキスト貼り付け）も可能。

**受け入れ基準**
- 他アプリの共有メニューに Rakuku が表示される。
- 共有実行後、ユーザーが追加操作なしで1件保存される（トーストやミニUI程度で完了）。
- 保存したアイテムがアプリ起動時に一覧へ反映される。

### 5.2 AI 解説・例文生成（Claude）

- 保存したアイテムの原文に対し、Claude が以下を**日本語で**生成する：
  - 意味・訳
  - ニュアンス／使いどころの解説
  - 例文（英語＋日本語訳）複数
- 生成はサーバ側（Supabase Edge Function）から Claude API を呼び、**APIキーをクライアントに露出しない**。
- 生成結果はアイテムに保存し、再表示時は再生成しない（キャッシュ）。
- 失敗時はリトライ可能なエラー状態として扱う。

**受け入れ基準**
- アイテム詳細で日本語解説と例文が表示される。
- 同一アイテムを再表示しても再課金されない（保存済みを表示）。
- 生成失敗時に再試行できる。

### 5.3 音声生成・再生（発音確認）

- アイテムの英語（表現・例文）を音声で再生できる。
- **MVPは端末内蔵TTS（`flutter_tts`）を採用**（無料・オフライン可）。
  - 将来クラウドTTS（高品質）へ差し替え可能なように `AudioClient` を抽象化する（§7.4）。
  - 端末TTSは都度合成のため音声ファイルの永続化は不要。クラウドTTS採用時のみ Supabase Storage（将来 R2 へ差し替え可能）に保存・再利用する。

**受け入れ基準**
- アイテム詳細から英語音声を再生できる。
- オフラインでも再生できる（端末TTS）。

### 5.4 単語帳・コレクション管理

- 保存アイテムの一覧表示（新しい順）。
- アイテム詳細表示（原文・解説・例文・音声・学習状態）。
- アイテム削除。
- MVPでは単一の既定コレクションで可。複数コレクション対応は将来拡張（データモデルは対応可能に設計）。

### 5.5 復習機能

2つのモードを提供する。

#### モードA：音声クイズ
- 英語音声を再生し、ユーザーが意味を思い出す → 解答（意味）を表示して自己採点（できた／できない）。

#### モードB：タイピング想起
- 日本語の意味を提示し、ユーザーが**英語をタイピングして回答**。
- 正誤判定は**完全一致**。前後の空白のみトリムし、大文字小文字を含めて完全一致した場合のみ正解とする（表記ゆれは許容しない）。

**共通**
- セッション単位で出題。**1セッションの既定出題数は10問**（将来設定可能に）。
- 各回答結果（正誤・日時）を学習状態として記録する。

**受け入れ基準**
- 2モードを選んで復習を開始できる。
- 回答結果が記録され、次回の出題順（§6.5）に反映される。

### 5.6 認証

- **匿名スタート**：初回起動でアカウント作成不要、匿名ユーザーとして即利用開始。
- **Google サインイン**：任意のタイミングでログイン。
- **昇格**：匿名ユーザーが Google ログインした際、それまでのデータを引き継ぐ（匿名→本登録の昇格）。
- Supabase Auth（匿名サインイン＋Google OAuth、`signInWithIdToken`）を利用。

**受け入れ基準**
- アプリ初回起動でログインなしに保存・復習ができる。
- Google ログイン後も既存データが保持される。
- 別端末で同じGoogleアカウントでログインするとデータがDownされる。

### 5.7 同期

- 認証済み（匿名含む）ユーザーのデータを Supabase に同期し、複数端末で共有。
- Row Level Security により「自分のデータのみ」アクセス可能。
- オフライン保存 → オンライン復帰時に同期。競合は「最終更新優先（last-write-wins）」を既定とする。

## 6. 非機能要件

| 区分 | 要件 |
|---|---|
| 6.1 性能 | アプリ起動から一覧表示まで体感2秒以内。AI生成は非同期で、保存操作をブロックしない |
| 6.2 オフライン | 保存・閲覧（生成済み）はオフラインで可能。AI生成・音声生成・同期はオンライン時 |
| 6.3 セキュリティ | Claude/TTS のAPIキーはサーバ側のみ保持。RLSで他ユーザーデータ遮断 |
| 6.4 コスト | 無料運用。Supabase無料枠内（DB 500MB / Storage 1GB / Edge Functions 50万回/月 / MAU 5万）。Claude/TTSコストは生成回数で発生（§9） |
| 6.5 復習出題ロジック（SRS代替） | MVPは簡易ロジック：未復習・直近誤答を優先し、次いで最終復習日が古い順。将来SRS（SM-2等）へ差し替え可能に設計 |
| 6.6 移植性 | 将来の自前サーバ＋自前DB移行を見据え、§7.4 の抽象化を必須とする |
| 6.7 可用性 | 無料枠のためSLAなし。Supabase無料プロジェクトは1週間無アクセスで停止するため、日次ヘルスチェックで凍結を回避する（§13） |

## 7. 技術スタック・アーキテクチャ

### 7.1 スタック

| レイヤ | 採用技術 |
|---|---|
| クライアント | Flutter（iOS / Android） |
| 認証 | Supabase Auth（匿名＋Google OAuth） |
| データベース | Supabase（PostgreSQL）＋ Row Level Security |
| ストレージ | Supabase Storage（音声ファイル）※将来 Cloudflare R2 へ差し替え可能 |
| サーバロジック | Supabase Edge Functions（Deno/TypeScript） |
| 生成AI | Claude（Anthropic API）※Edge Function経由 |
| 音声合成 | 未確定（端末TTS or クラウドTTS、§12） |

### 7.2 構成（概略）

```
[Flutter App]
   │  保存/同期(SDK)            ┌──────────────────────────┐
   ├──────────────────────────▶│ Supabase                 │
   │  認証(匿名/Google)         │  - Auth (GoTrue)         │
   │                           │  - PostgreSQL + RLS      │
   │  AI生成リクエスト          │  - Storage               │
   ├──────────────────────────▶│  - Edge Functions ──┐    │
   │                           └─────────────────────┼────┘
   │                                                 ▼
   │                                      [Claude API] / [TTS API]
   └─ 共有シート/インテントからの保存（OS連携）
```

- クライアントは Supabase SDK でDB・認証・ストレージへアクセス。
- AI解説・音声生成は Edge Function を介し、外部APIキーを秘匿。

### 7.3 主要画面（MVP）

1. 一覧（保存アイテム）
2. アイテム詳細（原文・解説・例文・音声・学習状態）
3. 保存（共有経由のミニUI＋手動追加）
4. 復習モード選択 → 復習セッション（音声クイズ / タイピング想起）→ 結果
5. 設定／アカウント（ログイン・昇格）

### 7.4 移植性のための設計原則（必須）

将来「Supabaseごとセルフホスト」または「自前サーバ＋自前DBへ移行」する際のコストを最小化するため、以下を実装規約とする。

- **データアクセス層（Repository）を必ず挟む**：UI/ロジックは Supabase SDK を直接呼ばず、`ItemRepository` 等のインターフェース越しにアクセスする。
- **標準SQLに寄せる**：PostgreSQL標準機能のみ使用。ベンダー独自拡張に依存しない（RLSはPostgres標準のため可）。
- **外部クライアントの抽象化**：`AiClient`（Claude）・`AudioClient`（TTS）・`StorageClient`（Storage/R2）をインターフェース化し、実体を差し替え可能にする。
- **便利機能への過依存を避ける**：Realtime等を使う場合も代替実装の当てを持つ。

> 移行ルート：① `pg_dump` でPostgresを吸い出し任意のPostgresへ投入、② Supabase一式をDockerでセルフホスト、のいずれも可能な構成を維持する。

### 7.5 実装言語と責務分担

**Flutter（Dart）で全処理を書くわけではない。** 役割を3つに分離する。

| 場所 | 言語 | 責務 |
|---|---|---|
| Flutterアプリ（クライアント） | Dart | 画面・UI、ローカル状態、Supabase SDK経由のDB読み書き、Edge Function呼び出し |
| Supabase DB | SQL | テーブル定義、RLS（行レベル権限）、マイグレーション |
| Supabase Edge Functions | TypeScript (Deno) | **秘密鍵が必要な処理のみ**（Claude中継・TTS中継） |

- 単語帳の保存・取得・同期・削除などは**サーバコードを書かず**、FlutterからSupabase SDKで直接DBへアクセスする（RLSが「自分のデータのみ」を保証）。
- Claude解説生成・TTS生成は、APIキー秘匿のため**Edge Function（TypeScript）経由**でのみ実行する。
- 従来型の自前バックエンドのようにCRUD用APIを手書きする必要はなく、コード量を最小化する。

## 9. 外部連携・コスト

| サービス | 用途 | コスト観点 |
|---|---|---|
| Supabase | 認証・DB・ストレージ・Edge Functions | 無料枠内で運用（§6.4）。無アクセス1週間で停止に注意 |
| Claude API | 解説・例文生成 | 生成回数に応じ従量。生成結果をキャッシュし再生成を避ける |
| TTS | 音声生成 | MVPは端末TTSのため**無料・コスト0**。将来クラウドTTS採用時のみ従量＋Storage容量 |

- AIコストは「1アイテムにつき原則1回生成してキャッシュ」で抑制。
- MVPでは生成回数の上限は設けない（コストはキャッシュ方針で抑制）。

## 10. 移植性・将来拡張ロードマップ

- **音声配信コスト最適化**：配信量が増えたらストレージを Cloudflare R2（egress無料）へ差し替え（`StorageClient` 抽象により低コストで移行可能）。
- **自前サーバ移行**：§7.4 の規約により `pg_dump` 移行 or セルフホストへ移行可能。
- **SRS導入**：`review_states` のSRSフィールド拡張で間隔反復へ。
- **通知**：リマインダー通知の追加。
- **収益化**：フリーミアム（AI生成回数・同期上限の解放等）。

## 13. 運用：Supabase 凍結回避（keepalive）

Supabase 無料プロジェクトは**1週間アクセスが無いと自動停止**される。これを避けるため、外部から日次でヘルスチェックを行う。

> pg_cron 等のプロジェクト内スケジューラは、プロジェクトが停止すると一緒に止まるため凍結回避には使えない。**外部からのpingが必須。**

### 構成
- **GitHub Actions（`.github/workflows/supabase-keepalive.yml`）** が毎日 06:00 UTC（15:00 JST）に実行。
- Supabase の `/auth/v1/health` と、`keepalive` テーブル（`supabase/migrations/20260604000000_keepalive.sql`）への REST クエリを叩き、DB活動を発生させる。

### 有効化の前提
1. リポジトリの **Secrets** に `SUPABASE_URL` と `SUPABASE_ANON_KEY` を設定する。
2. **スケジュール実行はデフォルトブランチ上のワークフローのみ動く**ため、本ワークフローをデフォルトブランチへマージする必要がある。
3. GitHub はリポジトリが60日間無活動だとスケジュールを自動停止する点に留意（手動 `workflow_dispatch` でも実行可）。

### 代替案
GitHub Actions が使えない／確実性を上げたい場合は、UptimeRobot や cron-job.org などの外部監視サービスから同URLを日次pingしてもよい。
