# Rakuku 要件定義書

> 英語学習アプリ「Rakuku（ラクク）」の MVP 要件定義書。
> 本書は「誰が読んでも同じ実装に到達できる」ことを目標に、確定事項・前提・未確定事項を明示する。

- **版**: v1.1（MVP）
- **最終更新**: 2026-06-04
- **ステータス**: 機能要件・非機能要件・UIルック（Indigo×ライト）すべて確定

---

## 1. 概要

| 項目 | 内容 |
|---|---|
| アプリ名 | Rakuku（ラクク） |
| ジャンル | 英語学習（出会った英語表現を保存して、AI解説・音声・復習で定着させる） |
| 対象プラットフォーム | iOS / Android（クロスプラットフォーム） |
| 開発フレームワーク | Flutter |
| バックエンド | Supabase |
| 生成AI | Claude（Anthropic） |
| 収益モデル | 無料（MVP）。将来の収益化は別途検討 |
| 主言語 | UI・AI解説ともに日本語 |

### 提供価値（コンセプト）

日常で出会った英語（Webページ・SNS・記事・チャットなど）を**アプリを開かずに最短手数で保存**し、
保存した表現を **Claude が日本語で解説・例文化**、**音声で発音確認**、**復習テストで定着**させる。
「保存のハードルを限りなく下げ、後からまとめて学習・復習する」体験を中心に据える。

## 2. スコープ

### 2.1 MVP に含む

- 共有（Share）経由でのコンテンツ保存（アプリを開かず保存）
- 保存表現に対する Claude による日本語解説・例文生成
- 保存表現の音声生成・再生（発音確認）
- 単語帳（コレクション）管理：一覧・詳細・削除
- アイテムのブックマーク（ブックマークのみ復習も可能）
- 復習機能：**タイピング想起（日本語の意味を見て英語を入力）の1モード**
  - ヒント（先頭1文字表示）／答えを見る（灰色で全文表示）
  - 出題数を 5 / 10 / 20 / 50 / 100 から選択
- 学習ステータス（未復習 / 苦手 / うろ覚え / 覚えた）の自動更新
- 認証：Google サインイン ＋ 匿名スタート（後から本登録へ昇格）
- 複数端末間のデータ同期

### 2.2 MVP に含まない（将来検討）

- プッシュ通知 / リマインダー
- SRS（間隔反復スケジューリング）※ §6.11 に簡易版の代替を定義
- 音声クイズ形式の復習（当初検討したが MVP から除外）
- フラッシュカード形式の復習
- 穴埋めテスト形式
- 収益化（課金・サブスク・広告）
- ソーシャル機能（共有・フォロー等）
- Web 版

## 3. 想定ユーザー（ペルソナ）

- **日本語ネイティブの英語学習者（中級）**。CEFR で **B1〜C1** 程度。
- 基礎文法・基本語彙は習得済みで、より自然な語彙・フレーズ・ニュアンスを伸ばしたい層。
- 日常的に英語に触れ、「出会った単語・フレーズを後でまとめて学習・定着させたい」ニーズを持つ。

## 4. 用語

| 用語 | 定義 |
|---|---|
| アイテム（Item） | 保存した英語1件。**英単語**または**英語フレーズ**。原文テキスト・出典・AI生成解説・例文・音声・学習ステータスを持つ |
| コレクション（Collection） | アイテムをまとめる単位（単語帳）。MVPでは既定の1コレクションのみ |
| 解説（Explanation） | Claude が生成する日本語の意味・コアイメージ・ニュアンス説明 |
| 想起テスト | 意味（日本語）を提示し、ユーザーが英語をタイピングして回答する復習モード（MVP唯一の復習形式） |
| ブックマーク | アイテムに付けられる印。ブックマークしたアイテムだけを復習対象に絞り込める |
| 学習ステータス | アイテムの習熟度を表す4状態：未復習 / 苦手 / うろ覚え / 覚えた（§5.9） |

## 5. 機能要件

### 5.1 コンテンツ入力・保存

アイテム（英単語／英語フレーズ）を以下の3経路で登録できる。**MVPの保存対象はテキストのみ**（URL本文取得・画像OCRは将来拡張）。

**経路A：共有から保存（アプリを開かず）**
- iOS の共有シート / Android の共有インテントから Rakuku を呼び出し、**アプリ本体を前面に出さずに**テキストを保存。
- 受け取る入力：選択テキスト（必須）、可能であれば出典 URL / アプリ名（任意・メタ情報）。

**経路B：アプリ内手動入力**
- アプリ内でテキストを直接入力／貼り付けして保存。

**経路C：アプリ内音声入力**
- アプリを起動し、英語を発話 → **端末の音声認識（STT）**でテキスト化。
- 端末STTが返す**認識候補（複数）からユーザーが選択**して確定・保存する。
- 端末STT機能を用いるためオンライン要否は端末・OS依存。

**共通の保存時挙動**
- オフラインでも保存はローカルに完了する（後で同期）。
- 保存直後は「未処理（AI解説・音声が未生成）」状態。AI生成は非同期で実施。

**受け入れ基準**
- 他アプリの共有メニューに Rakuku が表示され、共有実行で追加操作なく1件保存される。
- アプリ内の手動入力・音声入力からも保存できる。
- 音声入力では認識候補が提示され、選択して保存できる。
- 保存したアイテムが一覧へ反映される。

### 5.2 AI 解説・例文生成（Claude）

- 保存したアイテムの原文に対し、Claude が以下を**日本語で**生成する：
  - 意味・訳
  - **コアイメージ**の解説（その語・フレーズが持つ中心的なイメージ）
  - ニュアンス／使いどころの解説
  - 例文（英語＋日本語訳）複数
- 生成はサーバ側（Supabase Edge Function）から Claude API を呼び、**APIキーをクライアントに露出しない**。
- 生成結果は `explanations` テーブルに**DB永続保存**し、再表示時は再生成しない（DBから読むのみ）。
- 失敗時はリトライ可能なエラー状態として扱う。

**受け入れ基準**
- アイテム詳細で日本語解説と例文が表示される。
- 同一アイテムを再表示しても再課金されない（保存済みを表示）。
- 生成失敗時に再試行できる。

### 5.3 音声生成・再生（発音確認）

- アイテムの英語（表現・例文）を音声で再生できる。
- **MVPは端末内蔵TTS（`flutter_tts`）を採用**（無料・オフライン可）。
  - 将来クラウドTTS（高品質）へ差し替え可能なように `AudioClient` を抽象化する（§7.4）。
  - 端末TTSは都度合成のため音声ファイルの永続化は不要。クラウドTTS採用時のみ Supabase Storage（将来 R2 へ差し替え可能）に保存・再利用する。

**受け入れ基準**
- アイテム詳細から英語音声を再生できる。
- オフラインでも再生できる（端末TTS）。

### 5.4 単語帳・コレクション管理

- 保存アイテムの一覧表示（新しい順）。
- アイテム詳細表示（原文・解説・例文・音声・学習状態）。
- アイテム削除。
- MVPでは単一の既定コレクションで可。複数コレクション対応は将来拡張（データモデルは対応可能に設計）。

### 5.5 復習機能（タイピング想起）

MVPの復習形式は**タイピング想起の1モードのみ**。

**出題と回答**
- 日本語の**意味を提示**し、ユーザーが**英語をタイピングして回答**する。
- 正誤判定は**完全一致**。前後の空白のみトリムし、大文字小文字を含めて完全一致した場合のみ正解（表記ゆれは許容しない）。
- 「**回答する**」ボタンは**何度でも押せる**。
- **初回の「回答する」で完全一致しなかった問題は「不正解」として記録**する（1回でも外したら、その後正解しても不正解扱い）。
- ただし**正解の文字列を完全に入力し終える（＝完全一致する）まで次の問題に進めない**。不一致の間は入力し直して何度でも再回答でき、一致した時点で「次へ」進める。

**ヒント機能**
- 「ヒント」ボタンを押すと、正解の**先頭1文字だけ**を表示する。
- ヒントを使って正解した場合の扱いは学習ステータスに反映（§5.9）。

**答えを見る機能（カラオケ式ゴースト＋タイプ強制）**
- 「答えを見る」ボタンを押すと、回答入力欄に正解を**薄い灰色のゴースト文字**で表示する（カラオケのように上からなぞって打つUI）。
- 押した後は**誤字を受け付けない（タイプ強制モード）**。次に入力すべき**正しい1文字以外のキー入力はブロック**し、正しい文字を打つまで次の文字に進めない（学習アプリMikan風）。
  - 例：正解が `resonate` で `re` まで入力済みのとき、次に `z` を打っても入力されず、正しい `s` を打つまで進めない。
- 正しく1文字打つごとにゴースト文字が確定色に変わり、最後まで打ち切ると一致＝次へ進める。
- 答えを見た問題は学習ステータス「苦手」、正否は「不正解」として記録（§5.9）。

**出題セッション**
- 1セッションの出題数を **5 / 10 / 20 / 50 / 100** から選択（既定 10）。
- 対象アイテムが選択数に満たない場合は、ある分だけ出題する。
- 出題対象を「全アイテム」または「ブックマークのみ」に絞り込める（§5.8）。
- 出題順は §6.11 の簡易ロジックに従う。
- 各回答の結果（正否・ヒント使用有無・答え閲覧有無・日時）を記録し、学習ステータスを更新する（§5.9）。

**結果画面（テスト直後の振り返り）**
- セッション終了後、**出題した全アイテムの一覧を判定付きで表示**し、テスト直後にその場で見返せるようにする。
- 判定は○×ではなく**学習ステータスの3区分（覚えた／うろ覚え／苦手）**で示す（§5.9）。
- 一覧の各行には、表現（英語）・意味（日本語）・判定（ステータスバッジ）を表示し、各行から詳細（解説・音声）へ遷移できる。
- **正答数は「覚えた」の件数**で表示する（うろ覚え・苦手は正答に数えない）。あわせてステータス内訳（各件数）も表示する。
- 「もう一度」（同条件で再出題）／「終了」（一覧へ戻る）を選べる。

**受け入れ基準**
- 意味を見て英語を入力し、完全一致で正誤判定される。
- 「回答する」は何度でも押せ、初回で外した問題は不正解として記録される。
- 正解を入力し終えるまで次の問題に進めない。
- ヒントで先頭1文字が表示される。
- 「答えを見る」で灰色ゴースト表示になり、以後は正しい文字しか入力できない（誤字はブロック）。
- 出題数を5段階から選べ、ブックマークのみに絞って復習できる。
- 回答結果に応じて学習ステータスが更新される。
- 結果画面で出題アイテム一覧と各判定（覚えた／うろ覚え／苦手）を確認でき、正答数は「覚えた」の件数で表示され、各アイテムの詳細へ遷移できる。

### 5.6 認証

- **匿名スタート**：初回起動でアカウント作成不要、匿名ユーザーとして即利用開始。
- **Google サインイン**：任意のタイミングでログイン。
- **昇格**：匿名ユーザーが Google ログインした際、それまでのデータを引き継ぐ（匿名→本登録の昇格）。
- Supabase Auth（匿名サインイン＋Google OAuth、`signInWithIdToken`）を利用。

**受け入れ基準**
- アプリ初回起動でログインなしに保存・復習ができる。
- Google ログイン後も既存データが保持される。
- 別端末で同じGoogleアカウントでログインするとデータがDownされる。

### 5.7 同期

- 認証済み（匿名含む）ユーザーのデータを Supabase に同期し、複数端末で共有。
- Row Level Security により「自分のデータのみ」アクセス可能。
- オフライン保存 → オンライン復帰時に同期。競合は「最終更新優先（last-write-wins）」を既定とする。

### 5.8 ブックマーク

- 任意のアイテムにブックマークを付与／解除できる。
- 一覧を「ブックマークのみ」で絞り込み表示できる。
- 復習セッションの対象を「ブックマークのみ」に限定できる（§5.5）。

**受け入れ基準**
- アイテムのブックマークをON/OFFできる。
- ブックマークしたアイテムだけを一覧・復習で対象にできる。

### 5.9 学習ステータス

各アイテムは4つの学習ステータスのいずれかを持つ。**直近の復習結果**に応じて自動更新する。

| ステータス | 条件（直近のタイピング想起の結果） |
|---|---|
| **未復習** | まだ一度も復習していない（復習回数 0） |
| **覚えた** | ヒント未使用・答えを見ず、一発で正解した |
| **うろ覚え** | ヒントを使って正解した |
| **苦手** | 答えを見た／または自力で不正解だった（ヒント未使用で不正解も含む） |

- ステータスは**直近1回の結果で上書き**する（履歴の集計ではなく最新結果を反映）。
- 判定は**初回の「回答する」操作で確定**する：一発正解（ヒント・答えなし）=覚えた、ヒント使用で正解=うろ覚え、初回で外す／答えを見た=苦手。正解を打ち切るまで次へ進めない仕様（§5.5）でも、判定はこの初回操作で確定する。
- **結果画面（§5.5）の判定表示はこの3区分（覚えた／うろ覚え／苦手）を用い、正答数は「覚えた」の件数で数える**（○×は用いない）。
- ステータスは一覧・詳細でバッジ等として視認でき、§6.11 の出題順の優先度にも用いる。

**受け入れ基準**
- 復習結果に応じてステータスが上記ルールどおり更新される。
- 一覧・詳細で現在のステータスが確認できる。

## 6. 非機能要件

| 区分 | 要件 |
|---|---|
| 6.1 対応プラットフォーム | iOS 17+ / Android 12（API 31）+（上限は常に最新OS）。スマートフォン縦向き。タブレット・横向きは対象外 |
| 6.2 性能 | 起動→一覧表示 体感2秒以内 / タップ等の操作応答 100ms以内 / AI生成は非同期で保存操作をブロックしない |
| 6.3 オフライン | 保存・閲覧（生成済み）・端末TTS再生はオフライン可。AI生成・同期はオンライン時。音声入力STTはOS依存 |
| 6.4 同期 | 起動時＋フォアグラウンド復帰時に同期。競合は last-write-wins |
| 6.5 セキュリティ | Claude のAPIキーはEdge Functionのみ保持。全テーブルRLSで他ユーザーデータ遮断。通信はTLS |
| 6.6 プライバシー | 収集データは最小限。アカウント削除で当該ユーザーの全データを削除 |
| 6.7 可観測性 | MVPは**クラッシュ監視のみ**導入。利用分析（アナリティクス）は将来導入予定（§10） |
| 6.8 アクセシビリティ | 端末の文字サイズ設定に追従。十分なコントラストを確保（基本対応） |
| 6.9 UI言語 | 日本語のみ |
| 6.10 コスト | 無料運用。Supabase無料枠内（DB 500MB / Storage 1GB / Edge Functions 50万回/月 / MAU 5万）。Claudeコストは生成回数で発生し、生成結果のDB保存（再生成しない）で抑制（§9） |
| 6.11 復習出題ロジック（SRS代替） | MVPは簡易ロジック：ステータス優先度（未復習 > 苦手 > うろ覚え > 覚えた）→ 同優先度内は最終復習日が古い順。将来SRS（SM-2等）へ差し替え可能に設計 |
| 6.12 移植性 | 将来の自前サーバ＋自前DB移行を見据え、§7.4 の抽象化を必須とする |
| 6.13 可用性 | 無料枠のためSLAなし。Supabase無料プロジェクトは1週間無アクセスで停止するため、日次ヘルスチェックで凍結を回避する（§13） |

## 7. 技術スタック・アーキテクチャ

### 7.1 スタック

| レイヤ | 採用技術 |
|---|---|
| クライアント | Flutter（iOS / Android） |
| 認証 | Supabase Auth（匿名＋Google OAuth） |
| データベース | Supabase（PostgreSQL）＋ Row Level Security |
| ストレージ | Supabase Storage（音声ファイル）※将来 Cloudflare R2 へ差し替え可能 |
| サーバロジック | Supabase Edge Functions（Deno/TypeScript） |
| 生成AI | Claude（Anthropic API）※Edge Function経由 |
| 音声合成 | 端末内蔵TTS（`flutter_tts`）。`AudioClient`抽象で将来クラウドTTSへ差替可 |

### 7.2 構成（概略）

```
[Flutter App]
   │  保存/同期(SDK)            ┌──────────────────────────┐
   ├──────────────────────────▶│ Supabase                 │
   │  認証(匿名/Google)         │  - Auth (GoTrue)         │
   │                           │  - PostgreSQL + RLS      │
   │  AI生成リクエスト          │  - Storage               │
   ├──────────────────────────▶│  - Edge Functions ──┐    │
   │                           └─────────────────────┼────┘
   │                                                 ▼
   │                                      [Claude API] / [TTS API]
   └─ 共有シート/インテントからの保存（OS連携）
```

- クライアントは Supabase SDK でDB・認証・ストレージへアクセス。
- AI解説・音声生成は Edge Function を介し、外部APIキーを秘匿。

### 7.3 主要画面（MVP）

1. 一覧（保存アイテム。ステータスバッジ／ブックマーク絞り込み）
2. アイテム詳細（原文・意味・コアイメージ・ニュアンス・例文・音声・ステータス・ブックマーク）
3. 保存（共有経由のミニUI＋手動入力＋音声入力の候補選択）
4. 復習設定（出題数5/10/20/50/100・対象=全件/ブックマークのみ）→ タイピング想起セッション（ヒント／答えを見る）→ 結果
5. 設定／アカウント（ログイン・昇格）

### 7.4 移植性のための設計原則（必須）

将来「Supabaseごとセルフホスト」または「自前サーバ＋自前DBへ移行」する際のコストを最小化するため、以下を実装規約とする。

- **データアクセス層（Repository）を必ず挟む**：UI/ロジックは Supabase SDK を直接呼ばず、`ItemRepository` 等のインターフェース越しにアクセスする。
- **標準SQLに寄せる**：PostgreSQL標準機能のみ使用。ベンダー独自拡張に依存しない（RLSはPostgres標準のため可）。
- **外部クライアントの抽象化**：`AiClient`（Claude）・`AudioClient`（TTS）・`StorageClient`（Storage/R2）をインターフェース化し、実体を差し替え可能にする。
- **便利機能への過依存を避ける**：Realtime等を使う場合も代替実装の当てを持つ。

> 移行ルート：① `pg_dump` でPostgresを吸い出し任意のPostgresへ投入、② Supabase一式をDockerでセルフホスト、のいずれも可能な構成を維持する。

### 7.5 実装言語と責務分担

**Flutter（Dart）で全処理を書くわけではない。** 役割を3つに分離する。

| 場所 | 言語 | 責務 |
|---|---|---|
| Flutterアプリ（クライアント） | Dart | 画面・UI、ローカル状態、Supabase SDK経由のDB読み書き、Edge Function呼び出し |
| Supabase DB | SQL | テーブル定義、RLS（行レベル権限）、マイグレーション |
| Supabase Edge Functions | TypeScript (Deno) | **秘密鍵が必要な処理のみ**（Claude中継・TTS中継） |

- 単語帳の保存・取得・同期・削除などは**サーバコードを書かず**、FlutterからSupabase SDKで直接DBへアクセスする（RLSが「自分のデータのみ」を保証）。
- Claude解説生成・TTS生成は、APIキー秘匿のため**Edge Function（TypeScript）経由**でのみ実行する。
- 従来型の自前バックエンドのようにCRUD用APIを手書きする必要はなく、コード量を最小化する。

## 8. データモデル（主要テーブル・初版）

## 9. 外部連携・コスト

| サービス | 用途 | コスト観点 |
|---|---|---|
| Supabase | 認証・DB・ストレージ・Edge Functions | 無料枠内で運用（§6.10）。無アクセス1週間で停止に注意 |
| Claude API | 解説・例文生成 | 生成回数に応じ従量。生成結果を`explanations`にDB保存し再生成を避ける |
| TTS | 音声生成 | MVPは端末TTSのため**無料・コスト0**。将来クラウドTTS採用時のみ従量＋Storage容量 |

- AIコストは「1アイテムにつき原則1回だけ生成し、結果をDB保存して再利用」で抑制。
- MVPでは生成回数の上限は設けない（コストはDB保存・再生成しない方針で抑制）。
- （将来）`source_text` 一致の解説を全ユーザー横断で共有する辞書テーブルを設け、生成回数をさらに削減可能（MVPでは見送り）。

- **通知**：リマインダー通知の追加。

## 13. 運用：Supabase 凍結回避（keepalive）

Supabase 無料プロジェクトは**1週間アクセスが無いと自動停止**される。これを避けるため、外部から日次でヘルスチェックを行う。

> pg_cron 等のプロジェクト内スケジューラは、プロジェクトが停止すると一緒に止まるため凍結回避には使えない。**外部からのpingが必須。**

### 構成
- **GitHub Actions（`.github/workflows/supabase-keepalive.yml`）** が毎日 06:00 UTC（15:00 JST）に実行。
- Supabase の `/auth/v1/health` と、`keepalive` テーブル（`supabase/migrations/20260604000000_keepalive.sql`）への REST クエリを叩き、DB活動を発生させる。

### 有効化の前提
1. リポジトリの **Secrets** に `SUPABASE_URL` と `SUPABASE_ANON_KEY` を設定する。
2. **スケジュール実行はデフォルトブランチ上のワークフローのみ動く**ため、本ワークフローをデフォルトブランチへマージする必要がある。
3. GitHub はリポジトリが60日間無活動だとスケジュールを自動停止する点に留意（手動 `workflow_dispatch` でも実行可）。

### 代替案
GitHub Actions が使えない／確実性を上げたい場合は、UptimeRobot や cron-job.org などの外部監視サービスから同URLを日次pingしてもよい。
